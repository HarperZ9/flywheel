# CC-1 EXPERT-GROUNDING REQUIREMENTS
## What the implementation plan must carry

Status of this document: binding. Every requirement below survived three adversarial passes (fence guard, evidence honesty, implementability/non-extraction). Requirements the lenses killed are in Section 6 with the reason, so they do not get re-proposed.

Two rules govern the whole document.

**Rule A (grounding discipline).** A `grounded_in` string is shipping text. If a requirement and its falsifier survive deletion of its citation, the citation is illustrative and is marked as such or removed. No requirement below is load-bearing on a human-subjects finding transferred to a machine.

**Rule B (prohibition over prescription).** Across all six literatures the robust results are negative: confrontation harms, blame produces concealment, per-person scores do not predict individuals, far transfer does not occur, trigger warnings raise anticipatory anxiety, retrospective growth reports track distress. The positive prescriptions are smaller, more contested, and more often single-lab. Prohibitions ship as invariants. Prescriptions ship as revisable defaults with a stated review date and a `local calibration` tag.

## 0. PRECEDENCE AND SHARED DEFINITIONS

Twelve falsifiers below depend on these. Define them once, in the schema, before anything else is built.

**0.1 Receipt bytes.** `receipt_core` (hashed, deterministic): oracle id, oracle version hash, input hashes, config hash, derivation, verdict, negative-scope enumeration, `derivation_hops`. `receipt_envelope` (unhashed): wall-clock, duration, host, run id, nonce. Every identity claim in this document means "receipt_core hashes are equal." No requirement anywhere may say "byte-identical run."

**0.2 Accept-path whitelist (positive form).** A verdict is a pure function of `(input hashes, oracle version hash, config hash)` and nothing else. This one sentence subsumes every prohibition on ledger history, selector scores, learned models, operator confidence, and incident counts reaching a verdict. Tested by sandboxed replay: run the accept path with the ledger directory absent or unreadable and the curriculum selector disabled, assert identical `receipt_core` bytes. Do not attempt static information-flow analysis; it is undecidable in Python with dynamic imports and file IO.

**0.3 Oracle admission criterion.** An oracle is admissible only if it is deterministic, offline-runnable, pinned by container digest or lockfile hash, requires no network, and requires no licensed binary. An oracle that cannot meet this emits UNVERIFIABLE, never PASS. Floating-point and GPU nondeterminism, dependency drift, locale, and filesystem ordering are the known failure modes and are the oracle author's problem, not the ledger's.

**0.4 One string surface.** All user-facing strings live in a single localization file. CI asserts no user-facing string literal exists outside it. All copy lints run against that one file. Falsifiers written against a web DOM are rewritten against the Flutter widget tree and this file.

**0.5 Four lints, one owner each.**
- `fence-lint`: denylist over code identifiers, log strings, test names, receipt templates, UI strings, and published docs. Covers heal, forgive/forgiving, trauma, wound, scar, nurture, suffer, punish-as-verb-with-subject, resilient, child/childhood, developmental, generation, lineage, ancestor, inherit/inherited, epigenetic, and every clinical construct name. Explicitly **not** applied to commit messages, code comments, or private notes. `rolled back` stays legal for transactions and releases; it is banned only in repair-record templates.
- `model-facing-lint`: same denylist plus a ban on second-person address, praise, and affect, applied to every string the environment can emit toward the policy (task descriptions, system prompts, environment feedback, reward-log text). Falsifier: dump every env-to-model string, assert zero hits.
- `biography-lint`: no shipped page, README, model card, release note, or receipt template contains first-person history or an appeal to the author's experience as evidence for a design choice.
- `claim-lint`: adherence language permitted ("follows X's principles"), benefit language prohibited ("reduces shame", "trauma-informed care improves outcomes for users").

Each release emits a **fence conformance receipt**: denylist hash, surfaces scanned, hit count, enumerated exceptions with reasons. Without it the boundary is unauditable by a stranger, which is the actual test the scope note imposes.

**0.6 Precedence when requirements conflict.** Accept-path purity (0.2) > append-only > criterion stability > determinism/resumability > presentation rules. Curriculum selection and failure accounting are separate systems and never share a rule (see M-3).

**0.7 Deletion.** No selective deletion, amendment, redaction, archiving, or hiding of any record, ever. Total local erasure of everything is always available in one act, with a plain statement of exactly what remains and where, and it is tested.

## 1. THE PRACTITIONER CONTRACT

How the tool treats the fallible human using it. Twelve requirements.

### PC-1. No aggregate is ever computed over the person
**Requirement.** No persisted or exported field may be a reduction over more than one run's verdicts. Per-artifact and per-run history is unbounded and fully retained. Per-person scores, rates, streaks, risk bands, consistency indices, percentiles, and trend lines do not exist in the schema, the API, the export format, or any view.
**Grounding.** Anda, Porter & Brown 2020: the ACE instrument's own co-author publishing its bound, that it was built to research and not to screen, and that individual-risk inference is a misapplication. Baldwin et al. 2021: AUC 0.5 to 0.6 for 11 of 19 outcomes. A strong population signal can be near-useless as an individual classifier. This is the strongest grounding available anywhere in the set because it is an authority publishing the limit of his own instrument.
**Falsifier.** Schema audit over the quantity, not the key (there is no user table in an accountless app): any persisted or exported field that is a reduction over more than one run's verdicts fails. One derived per-operator statistic anywhere fails.
**Surface.** Store schema, export format, all views. Enforce at the schema level, not by UI review, so it survives future features.

### PC-2. Absence has no cost and leaves no trace
**Requirement.** No rendered value is a function of `(now − last_activity)`. No streaks, days-since, last-seen, welcome-back, inactive, catch-up, or overdue state. No outbound notification may fire on a condition that includes inactivity. Nothing expires.
**Grounding.** Primary: the project's non-extractive commitment, which is a stated design commitment and needs no empirical warrant. Secondary and narrow: Kirchner, Shiffman & Wileyto 2012 (1,001 lapse episodes, 203 smokers) found post-lapse self-blame and guilt did not predict relapse after a first lapse, which removes the evidential basis for both penalty framing and consolation copy. The defensible lever is structural re-entry cost, not affect.
**Falsifier.** Property test: assert no rendered value derives from `(now − last_activity)`. Denylist grep over the string file. Do **not** use pixel-identical screenshot comparison; receipt timestamps are legitimate provenance and will differ.
**Surface.** Home view, resume path, the notification layer (which does not exist).

### PC-3. Interruptible, resumable, byte-stable core
**Requirement.** Every long-running verification exposes an always-live stop control. Aborting appends a durable partial record with verdict UNDECIDED plus a resume token and never emits FAIL, never discards completed work. Resuming restores state in one action, recomputes no already-verified step, and produces `receipt_core` hashes for the completed prefix identical to an uninterrupted run. The interruption itself is appended as an operational incident in `receipt_envelope` scope; a resumed run's verdict chain matches, its incident log legitimately differs.
**Grounding.** Determinism. A verification system whose verdicts depend on whether the process was interrupted is not deterministic, and determinism is the product. Adherence to SAMHSA principle 5 (empowerment, voice and choice) is claimed; measured benefit is not. Do **not** ground this in Maier & Seligman stressor controllability; that is a claim about detectors inside organisms and the requirement survives its deletion intact.
**Falsifier.** Kill at 20 pseudorandom points across a long run plus one forced oracle-version bump. Assert `receipt_core` prefix hash equality, verdict UNDECIDED on every aborted record, exactly one action to resume, and zero changed hashes on pre-existing records.
**Surface.** Stop control in the run view, `cc1 resume`, workspace launch.

### PC-4. Failure copy addresses the artifact, never the person
**Requirement.** The grammatical subject of every verdict, error, and diagnostic string is a claim, receipt, derivation, oracle, or input. Required form on verdict surfaces: `<oracle name and version> <input identifier> <observed> vs <expected>`. No second-person fault construction, no evaluative adjective with a human referent, no apology token ("oops", "sorry", "something went wrong"), no exclamation marks, no reassurance or consolation copy. Verdict vocabulary is never softened or renamed: FAIL is FAIL, not "needs attention". Environment and IO faults (disk full, oracle binary missing, permission denied) get their own template and are exempt from the observed/expected requirement.
**Grounding.** Tangney & Dearing's behavior-versus-self distinction, narrowed to the intersection the Gausel & Leach critique also accepts: address the behavior, not the self. Gausel & Leach 2011 additionally establish that the operative variable is appraised audience exposure, not tone, which is why PC-8 (private by default) carries more of this load than the copy rule does.
**Falsifier.** Denylist over the single string file (0.4). Honest about what the check is: a token denylist plus a documented human review item, not a parser. "Grammatical subject" is not machine-checkable without NLP that will not be written.
**Surface.** All FAIL/UNDECIDED/UNVERIFIABLE views, CLI stderr, the one string file.

### PC-5. Verdict presentation is invariant to consequence magnitude
**Requirement.** Two identical process failures with blast radii of 1 and 200 render with identical verdict typography, color token, and iconography. Blast radius is displayed as a labeled factual count and may inform queue sort order. A pre-result element is permitted **if and only if its text changes when the underlying data changes**; an element whose text is constant regardless of data is an affective warning and is prohibited.
**Grounding.** Outcome bias (Baron & Hershey 1988) is well replicated; the design inference that constant typography reduces outcome-biased reading is *consistent with* the finding, not evidenced by it. The pre-result discriminator is grounded in Bridgland, Jones & Bellet 2024: content warnings show no reliable effect on affective response or outcome and reliably increase anticipatory anxiety.
**Falsifier.** Snapshot test rendering the same verdict at blast radius 1 and 200: identical CSS/theme tokens for the verdict element. Separate test: every pre-result element's text must differ across two different data states.
**Surface.** Verdict badge component, FAIL view, run queue ordering.

### PC-6. Doubt is answered with records, in one action, offline
**Requirement.** From any verdict, one action reaches: oracle id and version hash, input hashes, config hash, the full derivation, the negative-scope enumeration, and a copyable re-derivation command. No confirmation dialog, no expand-then-expand, no network dependency. The derivation is expanded by default; the negative-scope block renders at the same visual weight as the verdict. Modal confirmations are permitted only for actions irreversible outside the tool's control, and each carries an in-source justification naming the external system that makes it irreversible.
**Grounding.** Dekker's restorative formulation, that an account is something you get people to tell and others to listen to. The stranger-offline-reproducibility bar carries this independently.
**Falsifier.** For every verdict type, count interactions to the evidence bundle: any count above 1, or any blocking element in the path, fails. The displayed command, run in a clean offline container, must reproduce the verdict. Enumerate every modal in the codebase: any confirmation guarding a reversible action, or lacking a justification comment, fails.
**Surface.** Verdict detail panel, `cc1 explain <receipt>`.

### PC-7. No repair is auto-applied; batches are one reviewed diff
**Requirement.** No fix, format, or suggestion is ever applied without an explicit human act. Repair is presented as a proposal with the full diff and a receipt of what the change would and would not establish. Batch application is permitted only when the complete set renders as one reviewable diff carrying a content hash of the batch, the application is one explicit act, and the ledger records every member individually.
**Grounding.** Miller & Rollnick's righting reflex, the best-evidenced prohibition in the therapeutic-change literature (directive/confrontational style predicts dropout, weaker alliance, and worse outcome). Deci & Ryan autonomy support, cited as modest and heterogeneous. Note that forcing 200 individual commits for a decision the person already made is sludge by the environment domain's own definition; the evidence is about the tool deciding, not about batching execution of a human decision.
**Falsifier.** Static analysis of all write paths to user artifacts: any path reachable without a displayed diff and a distinct human commit event fails. Any batch write without a batch content hash in the record fails.
**Surface.** Repair proposal view, `cc1 repair --apply`.

### PC-8. Records are private by default; zero egress is asserted, not promised
**Requirement.** No telemetry, no background sync, no crash reporter, no update check, no font fetch, no share prompt after a failure. Publication of any receipt or ledger segment is an explicit, per-artifact, reversible-before-commit act with the exact bytes shown first. Each release ships an egress receipt produced by an instrumented full-session run with all sockets captured.
**Grounding.** Gausel & Leach 2011: what predicts defensive concealment versus repair is appraised exposure to a condemning audience, not the wording of the message. Architectural separation, per the ASRS design, is the mechanism; gentle tone is not. ASRS is an existence proof (2M-plus reports over roughly 47 years with no recorded confidentiality breach); it is not evidence that any safety outcome followed.
**Falsifier.** Any outbound connection observed during the instrumented session fails. A release missing its egress receipt fails.
**Surface.** Network layer, `receipts/egress.json` in the release artifact, publish flow.

### PC-9. Shared-device threat model, tested
**Requirement.** Assume a second person opens the machine and is already authenticated. No record content appears in window titles, OS notifications, recent-file lists, or taskbar previews. The app ships no crash reporter and disables OS dump generation for its process. Full export and full local erasure are available from inside the app with a plain statement of exactly what remains afterward and where. The residual is stated honestly, not asserted away.
**Grounding.** PenzeyMoog 2021: failing to explicitly design for vulnerable users implicitly designs for their abuser, and the relevant adversary is often physically present. Local-first with no account removes remote exposure and concentrates this risk.
**Falsifier.** Scripted-session scan of window titles, notification payloads and OS recent items for any substring of record content. After `erase --all`, scan the filesystem and OS caches; any residue not named in the app's own statement fails.
**Surface.** Window title builder, OS integration layer, `cc1 erase --all`.

### PC-10. The non-punitive posture ships with a narrow, published exclusion list
**Requirement.** Fabricated, forged, or hash-inconsistent receipts are hard-blocked and are not recoverable failures. The exclusion list is enumerated on the product surface directly next to the non-punitive claim, so the guarantee reads as bounded rather than absolute.
**Grounding.** ASRS immunity design: protection is credible because its exclusions are narrow and published. State the bound honestly: ASRS is n=1 with no counterfactual, so the causal contribution of exclusion-list narrowness is untested. What is defensible is that an unbounded amnesty claim would be false, because forgery must be blocked.
**Falsifier.** Exclusion list absent from the public surface fails. A receipt whose content hash does not match its stated derivation accepted into the ledger in any state other than hard rejection fails.
**Surface.** Docs page, ledger write path.

### PC-11. Published sludge audit, machine-generated
**Requirement.** A script drives the UI and generates a table of measured step counts, required fields, and elapsed times for every matched add-path/remove-path pair: import versus export-everything, enable versus disable, install versus uninstall-and-purge, start-using versus leave-with-all-data. No remove-path may exceed its add-path on any of the three measures. Regenerated every release.
**Grounding.** Sunstein 2022 sludge audits; OECD 2024. Sludge requires no effect-size claim to be useful, which is why it survives the collapse of the surrounding nudge literature.
**Falsifier.** A hand-written or stale table fails. Any pair where the remove-path exceeds the add-path fails.
**Surface.** `docs/sludge-audit.md` generated by `scripts/sludge_audit.py`.

### PC-12. Findability and dissent
**Requirement.** (a) The practitioner can search, filter and sort their own record on demand, including sorting by recorded timestamp. A sort the person asks for is not a nudge; the banned object is a quantity derived from their absence. (b) View filters are permitted, are off by default, are per-session, and render a persistent visible count of what is currently filtered out. No default view omits failures. (c) `cc1 note --dissent <receipt>` appends a record of kind `dissent` that is clearly not a verdict, is never counted in any aggregate, and never changes any verdict rendering. UNDECIDED still cannot be promoted to PASS by any operator action; the sanctioned strong form of disagreement is replacing the oracle, which mints a new criterion epoch.
**Grounding.** Practitioner sovereignty: expertise informs the practitioner, it never overrides them. Without an append-only dissent record, sovereignty exists only up to the point where the person disagrees with the tool. The findability rule closes a gap the other rules created: banning recency defaults, elapsed-time strings and away-summaries left no specified path back to work left three weeks ago.
**Falsifier.** Assert a dissent record never enters any verdict computation or aggregate. Assert `erase --all` still works. Assert no filter state persists across sessions and that the filtered-out count is always visible when a filter is active.
**Surface.** Record browser, `cc1 note --dissent`, filter chip component.

## 2. FORGIVING CIRCUMSTANCES, STATED AS MECHANISM

The phrase does not appear in code, logs, receipts, tests, UI, or docs. It cashes out as the following. This block is the canonical reading of STRICT TRUTH, GENTLE CONSEQUENCES on the training side, and everything else refers to it rather than restating it.

> **Bounded consequence, invariant criterion.** Strictness lives entirely in the criterion. Boundedness lives entirely in the consequence. Concretely, and only this:
> (a) no state is unrecoverable outside a declared terminal set;
> (b) no verdict depends on attempt history;
> (c) sampling weights are never a function of past verdicts and never fall to zero;
> (d) an interrupted run resumes from its last appended receipt;
> (e) the criterion is frozen and content-addressed per run.

**M-1. Accept-path whitelist.** As 0.2. Maps to the existing invariant that no learned model sits on the accept path, hardened from a prohibition list into a positive definition, and made testable by sandboxed replay rather than by undecidable static analysis.

**M-2. Criterion identity.** Oracle set, oracle versions, thresholds and verdict rules hash into a `criterion_id`. Any change mints a new id and a new epoch. Prior receipts are relabeled "issued under criterion vN" and never recomputed in place. Cross-epoch comparison renders UNVERIFIABLE, never a delta. Every semantic change emits a criterion-change receipt containing prior and new definition plus hashes. *Grounding: measurement interpretability alone. A verdict is only interpretable relative to the criterion it was computed against; a mutable criterion makes FAIL meaningless and makes preregistered uplift uncomputable. No psychology required, and four domains independently proposing this is not four literatures corroborating it.* Maps to: criterion stability, append-only ledger.

**M-3. History independence, with fixed support.** Selection and accounting are separate systems.
- *Selection* may depend on past verdicts. It is a preregistered pure function, every item keeps a declared non-zero floor probability, nothing is ever blacklisted or removed from the sampling distribution, and selector scores never enter `receipt_core`.
- *Accounting* is history-independent: no down-weighting to zero, no penalty term, no threshold that moves with attempt count.
- Falsifier: force a check to FAIL 50 times, then PASS; diff the passing `receipt_core` against a first-attempt PASS. Any difference fails. Separately assert the enabled-action set, defaults, thresholds and copy template IDs are identical at attempt 1 and attempt 50, compared as sets, explicitly excluding record content and counts (which necessarily differ).
Maps to: entropy guard, accept path.

**M-4. Resumable runs.** Recovery from any interruption (process kill, corrupt cache, oracle version bump, disk full) restores to the last valid receipt, discards no subsequent valid work, emits its own receipt, and rewrites nothing. Chaos test at 25 pseudorandom kill points plus one forced version bump; hash every pre-existing receipt before and after. Maps to: resumable runs, append-only ledger.

**M-5. Recoverable incidents, with a declared terminal set.** Enumerate incident classes from the environment's own error taxonomy. Every class has a declared resume path or is listed in the pre-declared terminal set. Publish the **incident-recovery rate**: the fraction of observed FAIL incidents from which a resumed run reached a terminal verdict within a declared step budget. This replaces reachability analysis over the environment state space, which is intractable for anything past a toy environment and would yield a number nobody can compute. Maps to: exclusion ledger (the terminal set is an exclusion ledger), run report.

**M-6. Diversity floor.** Declare a diversity statistic appropriate to the actual training procedure (policy entropy for policy-gradient methods; a declared distinct-solution or coverage statistic for rejection-sampling or filtered-fine-tuning harnesses, which have no policy entropy in the relevant sense). Declare a floor before the run as an explicit local calibration. Record the series every step. A breach is flagged, appended as an incident, and reported in the run report. **Never auto-halt**: halting destroys the trace that makes the collapse measurable. Publish the full trace whether or not it breached, and publish runs that breached alongside runs that did not.
*Single grounding: Cui et al. 2025, arXiv:2505.22617, tagged preliminary (a preprint with a fitted empirical relation and several competing mitigation proposals from the same year), plus Amodei et al. 2016 safe exploration, tagged agenda-setting problem taxonomy and not an empirical result. No human-behavioral literature grounds this. The four independent groundings previously attached to it (organizational failure taxonomy, exposure variability, associative learning, clinical acceptance) manufactured the appearance of replication out of one preliminary source and are struck.*
Maps to: entropy guard.

**M-7. UNDECIDED and UNVERIFIABLE never collapse into FAIL.** Not in any reward term, scalar, aggregate, chart axis, or rendered summary. Property test: substituting UNDECIDED for FAIL in any input record must change the output; any output invariant under that substitution has collapsed the categories and fails. *Grounding: signal validity. Collapsing UNVERIFIABLE into FAIL injects label noise of unknown sign into the objective and makes the measured pass rate uninterpretable. The custodial-record argument (a system that reports "I could not check" as "you were wrong" about the operator's own work) applies to the human surface only and does not cross to reward shaping.* Maps to: verdict vocabulary, run report.

**M-8. Difficulty schedule.** Tiers are explicit. No tier transition occurs without a logged config-change event. Within-tier difficulty is drawn from a declared distribution with nonzero variance, asserted against the declared distribution to a stated tolerance. Monotone difficulty traces are **not** failed by fiat; there is no measurement warrant that monotonicity is harmful for this task class, and the requirement's real content is testable without that clause. Maps to: preregistration, run manifest.

**M-9. Provenance depth.** `derivation_hops` is a mandatory non-nullable integer on every receipt: 0 means this artifact was re-derived against the oracle in this run, n > 0 means the verdict is propagated from an ancestor n derivation steps away. A receipt lacking it is malformed and cannot be written. `(verdict, hops)` maps to a rendered token by a pure function with an exhaustive unit test; hops > 0 renders as `PASS-PROPAGATED` or as UNDECIDED-pending-re-derivation, never as a bare PASS. The negative-scope block auto-appends a non-suppressible sentence: *"This verdict was not re-derived on this artifact. It is propagated from `<hash>` across N derivation steps."* Inheritance vocabulary is banned; propagation vocabulary is used. Maps to: no receipt no accept, receipts state what they do not prove.

**M-10. Carrier attribution.** Before any claim that a behavior persists across checkpoints or versions, name the carrying artifact by content hash (dataset file, seed, oracle version, curriculum entry, prompt template). A persistence claim with no named carrier records UNVERIFIABLE, never PASS. Stronger test, and the only requirement in the set that can actually catch a false persistence claim: swap the named carrier between two runs; if the behavior does not follow the carrier, the attribution was wrong and the receipt is retracted by appended amendment. Also: declare an inter-episode state-erasure boundary and a machine-readable `carryover_manifest` enumerating with hashes everything permitted to survive it; differential-test two episodes with identical inputs and divergent hidden histories for byte-identical trajectories except manifest-listed items. Maps to: append-only ledger, UNVERIFIABLE.

**M-11. Model-facing strings.** As 0.5. This is the highest-risk uncovered surface in the original set: every proposed lint was scoped to user-visible copy, leaving task descriptions, system prompts, environment feedback and reward-log text unguarded. That is exactly where "you failed", "try again", "good job" enter, and second-person address plus affective framing does double damage there: it anthropomorphizes, and it puts preference-shaped signal on a verification-only path. Maps to: no preference reward, accept-path purity.

**M-12. Environment defects are reported as environment defects.** A diversity-floor breach, an unrecoverable incident outside the declared terminal set, and an eval-composition divergence beyond tolerance are all classified in the run report as defects of the environment. They are never reported as model failures and never enter the uplift numerator or denominator without being named. Maps to: run report, preregistration.

**M-13. Model-emitted anthropomorphic output.** If a trained model emits self-referential distress language, apology, or claims about its own experience, that output is recorded verbatim as data. It is never quoted on a product surface as evidence of anything about the model, never used as a training signal, and never used as an evaluation criterion. This is a genuinely new mechanism and is justified by the accept-path invariant: rewarding or displaying such output is preference reward and preference display under another name.

## 3. ACCOUNTABILITY STRUCTURE

What the just-culture and restorative literature requires of the receipt, ledger and contest design, and how a record stays honest without becoming a pillory.

**A-1. Repair record schema.** Four required fields, named as provenance engineering:
- `failed_claim_ref`: identifier and content hash of the specific claim that failed.
- `affected_derivations`: computed from the dependency graph, never operator-typed.
- `corrected_derivation` plus `rederivation_command`.
- `regression_guard`: a named check that demonstrably FAILS against the pre-repair state and PASSES against the post-repair state.
There is **no field, prompt, or free-text box anywhere in the product soliciting remorse, reflection, apology, or "what did you learn."** *Grounding: this is ordinary provenance engineering and needs no restorative-justice justification. The relevant historical note, kept internal: a five-element accountability framework maps seductively onto these four fields plus contrition, and the fifth element is excluded deliberately, because mechanizing contrition converts accountability into performance and a required contrition field will be filled with whatever unblocks the gate, corrupting the record. Naming the exclusion is safer than silence, because a later designer will rediscover the list and try to complete the set.*
Falsifier: a repair committed with an absent or empty `regression_guard` renders as a completed repair; or any affective field exists anywhere; or `affected_derivations` is operator-typed.

**A-2. Propagation is a derived view, not a stored state.** When a claim flips to FAIL, dependent verdicts do not mutate and are not re-badged in place. The append-only log stays authoritative; inherited status is computed at read time through a rebuildable index and rendered via `derivation_hops` plus a `rederivation_required` flag. Correctness assertion: drop the index, rebuild from the log, get the same answer. Do not mint a fifth verdict state and do not perform eager transitive-closure propagation writes; that is a mutation plus unbounded write amplification on a local store, for a strong-consistency guarantee nobody needs with one process and one user. *Grounding: dependency invalidation. A verdict is a claim about a content hash, so falsifying an ancestor withdraws the warrant of every derivation that consumed it. Do not ground this in "who is hurt, what do they need"; artifacts are not injured parties, and installing them as parties licenses the whole consequence vocabulary one step further out.*

**A-3. Decision-time information state.** Every verdict record carries, in `receipt_core`: oracle id, oracle version hash, input corpus hash, config hash, toolchain and dependency versions. A later oracle version producing a different result appends a **new** verdict with its own as-of context. It never mutates, overwrites or re-badges the historical verdict. Falsifier: bump the oracle version and re-run; if any historical verdict's stored value, badge or color changes, the record is being rewritten by hindsight. Also fails if a verdict renders without its as-of oracle version reachable in one action. *Grounding: local rationality and second-story practice from the blameless-postmortem tradition (industry doctrine, not controlled evidence), plus the fact that hindsight bias and outcome bias are among the most replicated findings in judgment research.*

**A-4. Repair kinds are distinguished.** `INSTANCE-CORRECTED` (this claim now verifies) versus `MECHANISM-CHANGED` (a regression check now guards the generating condition, and it demonstrably fails on the pre-repair state). Instance-only repairs are permitted, recorded, and never scolded, and they must not render identically to mechanism repairs. The run report shows the ratio. *Grounding: the transformative-justice argument that repairing an incident without changing its generating condition reproduces it, and the resilience-engineering argument that adaptive capacity must exist before the boundary event, arrive at the same operational rule from opposite fields. Both are theoretically established and empirically weak in their own literatures; the nearest implementable proxy is exactly the regression check specified here, so the requirement stands on the proxy.*

**A-5. Supersession, not reversal.** A repair receipt carries a resolvable pointer to the pre-repair record, states in its negative-scope block that the prior state persists and was not erased, and is produced by a new measurement rather than a relabeling of the old one. Wording: *"A later receipt supersedes this verdict; the prior record is retained and remains resolvable."* The blocklist on "reversed", "undone", "cleared", "rolled back", "fixed the original" applies to repair-record templates and shipped strings only. Falsifier: a repair receipt whose pre-repair pointer does not resolve; or a query for the pre-repair state returning not-found after a repair, which would mean the ledger rewrote rather than appended.

**A-6. Negative scope is structured, not prose.** Every receipt carries a non-empty enumeration derived from the oracle's declared coverage manifest: checks not run, inputs not inspected, properties not asserted. A receipt with an empty or missing negative-scope enumeration is rejected at write time. The enumeration must differ across oracles whose coverage differs; a static template identical across structurally different oracles fails. Every FAIL additionally carries a non-empty `not_inspected` array; a FAIL asserting a single named cause with an empty `not_inspected` fails validation and is not emitted.

**A-7. No adjudication of the person.** No culpability decision tree, no substitution test, no "was this negligent" assessment, no single-root-cause field, no Five Whys. Failure classification, if present, is derived deterministically from oracle output and is not assignable or editable by the operator or by any model. Proposed deterministic mapping: precondition-violation (a stated precondition evaluated false) / interaction-failure (all preconditions held, composite check failed) / hypothesis-disconfirmed (the run was preregistered as exploratory against an unresolved criterion). Identical failing evidence always produces identical classification. Falsifier: feed identical failing evidence twice and get two classes; or find any API, config or UI affordance that overrides a class. *Grounding: self-assigned culpability categories are the documented affordance that gets gamed, and CC-1 has deterministic oracles, so it never needs to adjudicate a person.*

**A-8. How the record stays honest without becoming a pillory.** Five structural properties, each already specified above, listed together because this is the question the literature actually answers:
1. **No condemning audience.** Private by default, zero egress asserted by receipt, per-artifact explicit publication (PC-8). This is the mechanism. Tone is not.
2. **No standing judgment of the person.** No aggregate over the person (PC-1). Prior FAILs remain individually retrievable forever; they are never summarized into a score.
3. **No outcome-scaled condemnation.** Verdict presentation invariant to blast radius (PC-5).
4. **Repair on top, never tidying.** Append-only, no deletion or hiding of any record, plus total local erasure of everything as the escape hatch (0.7).
5. **A bounded guarantee.** The published narrow exclusion list (PC-10). An unbounded "nothing you do here counts against you" is both false and corrosive to the guarantee's credibility.

**A-9. The ledger is write-only with respect to the accept path.** Subsumed by 0.2 and tested by sandboxed replay with the ledger unreadable. *Grounding: architectural separation between the reporting channel and the evaluating authority is the mechanism by which a protected channel becomes trustworthy at scale; exhortation is not.*

**A-10. Citation-state receipts.** Groundings decay: one flagship nudge meta-analysis required a published correction for including a retracted study; the canonical sleep-and-memory review was downgraded by its own senior author eight years later; a three-decade-old punishment-fallout claim was narrowed in 2021. Since CC-1 publishes its groundings and its records are append-only, it uses the same mechanism it uses for oracles: a **citation-change receipt** appends the new evidence state without rewriting the original, and affected surfaces are labeled "grounded under citation state vN."

**A-11. Grounding surface discipline.** For any requirement that ships: (a) the public-facing rationale must be statable in mechanism vocabulary with no citation to a human-suffering literature; (b) every published grounding mechanically carries its confidence tag and its strongest disconfirming null on the same surface, using the same auto-append device as M-9; (c) a grounding whose requirement and falsifier survive its deletion is marked `illustrative, not load-bearing` or removed; (d) no number that was not read in the primary source appears anywhere, including internal docs, because internal docs become public surfaces. Falsifier: pick ten requirements at random, strike every human-subject citation, and check the requirement and its falsifier still stand.

## 4. LEARNING DESIGN

### Measurement (the part that protects the headline bar)

**L-1. Primary uplift endpoint is a delayed re-derivation on held-out items.** The delay is preregistered before any training run begins, with a stated reason. It is never the end-of-training accept rate. Falsifier: the preregistration hash timestamp must precede the first training receipt timestamp; a primary endpoint measured at or within the training window fails; a missing delay field fails.
*Grounding: Roediger & Karpicke 2006 showed restudy beat testing at 5 minutes and lost to it at 2 days and 1 week. This is a rank reversal, not a magnitude claim that might shrink under replication: an immediate endpoint does not merely add noise, it can select the wrong regime outright. The requirement also survives deletion of the citation, because held-out-at-delay evaluation is independently mandatory ML hygiene.*

**L-2. Measurement and training probes are disjoint by construction.** Tagged separately, budgeted separately, reported separately. The retention estimate must be computable from measurement-tagged probes alone, and removing all training-tagged probes must not change it. Enforced by set intersection over content hashes, not by discipline. *Grounding: retrieval is itself a learning event (Rowland 2014), so an untagged probe pool contaminates the estimate it produces.* Promote this to a global invariant: any artifact entering an evaluation may not have entered a training update.

**L-3. Eval composition is published for both arms.** Task-type proportions, difficulty bins, source distribution, for treatment and control. If composition differs beyond a preregistered tolerance, the run reports UNVERIFIABLE rather than an uplift number. A matched-composition re-weighting is computed and published next to the raw estimate. Falsifier: a published uplift figure with no composition vector; or re-weighting moves the point estimate outside the reported interval and the page did not already say so. *Grounding: cell-type composition confounding in human epigenome-wide studies, which is not an analogy but the identical failure mode in a different substrate: an apparent difference between groups that is actually a difference in what was in the sample.*

**L-4. No bare PASS stands for an uplift claim.** Every claimed improvement ships a point estimate with an interval. The preregistration declares a minimum effect of interest, a target N, a power calculation against that MEI, and a stopping rule, all before the run. An effect distinguishable from zero but below the declared MEI is reported as PASS on the significance test and NULL on the claim, both shown. Without a preregistered stopping rule, optional stopping inflates every published estimate and an honest-nulls policy does not protect against it.

**L-5. Multiplicity control at two levels.** *Within a measurement:* declare `tests_planned`; the receipt records `tests_run` and the correction applied; `tests_run > tests_planned` renders UNDECIDED until a timestamped appended amendment is filed. An excess-significance check runs automatically as a computed p-value against a declared alpha, reporting "insufficient tests" below a stated k rather than firing on every small all-positive family. *Across the registry:* publish preregistrations filed versus completed versus published; report any uplift claim against that denominator; abandoned preregistrations remain visible.

**L-6. The analysis pipeline is frozen too.** Criterion freezing covers oracles; it must also cover the script that turns receipts into an uplift number, by content hash, committed at preregistration time. Exclusion rules for malformed runs, the treatment of UNDECIDED and UNVERIFIABLE in the denominator, outlier policy, and choice of summary statistic move point estimates as much as thresholds do.

**L-7. A replication bar, distinct from the reproducibility bar.** Re-running the same command on the same inputs and getting the same bytes says nothing about whether an uplift estimate holds in a second, independently sampled run. Every cautionary tale imported into this document is a replication failure, not a reproducibility failure. Add a third published measure: an independent re-run under a fresh seed and a fresh eval sample, published as a separate estimate, with both intervals shown together and **no pooling**.

### Probes and difficulty (training environment)

**L-8. There is no probe scheduler on the human side.** Retention probes exist in the training environment and apply to the model. The practitioner pulls a probe on demand; nothing is ever marked due, pending, or overdue. *Reason: a scheduler that decides when the person should be probed creates a due-state, and a due-state is a streak with a different name. It accumulates during absence, makes absence costly, and cannot exist without the tool modeling the person's retention, which PC-1 forbids.*

**L-9. Probe interval is preregistered, held constant, and marked local calibration.** No literature ratio ships as a default. The commonly cited 10 to 20 percent of retention horizon derives from verbal paired-associate and nonsense-syllable recall in humans and has no published validation for derivational or procedural verification tasks. The horizon-required-or-refuse-to-schedule rule is sound and stays.

**L-10. Probes are retrieval-first and composition-mixed.** The candidate answer is committed and hashed before the reference derivation is exposed; the oracle then returns the verdict together with the full derivation, never the verdict alone. Probe composition mixes task families in randomized order rather than blocking by family, recorded in the receipt so a stranger can verify it. *Grounding: mixed-composition evaluation is defensible measurement hygiene on its own terms. The interleaving evidence (Rohrer, Dedrick & Stershic 2015: d = 0.42 at 1 day, 0.79 at 30 days) comes from 126 seventh-graders doing mathematics problems and does not license a specific family count. The number three, previously specified, was invented.*

**L-11. Difficulty targets a band, never a ceiling.** The band is configurable, its bounds are recorded per run, and no citation is attached to the specific numbers. The only inherited falsifier is that a configuration whose upper bound is 100 percent fails, plus a scheduler-adjustment log when observed pass rate leaves the band in either direction. *Note for the implementer: there is a directly relevant optimization-side result, Wilson, Shenhav, Straccia & Cohen, "The Eighty Five Percent Rule for optimal learning," Nature Communications 2019 (moderate confidence on the exact citation, high confidence such a paper exists and derives roughly 85 percent analytically for stochastic gradient learners). If the band's upper bound comes from there, verify the primary source and cite it, because that source is actually about the thing being configured. If it does not, ship the bounds as an unattributed local calibration with no citation. Do not cite plasticity-training design statements or associative-learning theory for a number neither supplies.*

**L-12. Prerequisite gating on demonstrated passes.** Escalated difficulty is not scheduled for items whose declared prerequisites have never produced a PASS; the scheduler logs "difficulty deferred, prerequisite unmet". The floor is stored as a local calibration with a note that no literature constant exists. *Grounding: the desirable-difficulties tradition states its own boundary qualitatively (a difficulty without prerequisite knowledge becomes undesirable) and supplies no threshold. Do not present any number here as a literature constant.*

**L-13. Errorful practice only where corrective feedback is guaranteed and attributable.** Any attempt with a FAIL or UNVERIFIABLE verdict and no linked feedback artifact past the configured delivery deadline is withdrawn from training statistics and the incident is logged. *Grounding: Baddeley & Wilson 1994, where all 16 amnesic participants learned better when prevented from erring, because implicit memory cannot discriminate a correct response from an emitted error. Stated as a general engineering constraint rather than a clinical one: in a system that can drop, defer, or fail to attribute feedback, errorful practice is net harmful for the un-fed-back fraction.*

**L-14. Confidence is recorded, never coupled, never solicited.** On the model path, a pre-verdict confidence value may be derived mechanically (logprobs, self-consistency spread) and logged outside the accept path, purely so calibration curves can be published. It **must not** modulate feedback depth. Return the fullest correction available on every FAIL, unconditionally. The human is never asked to self-report confidence.
*Reason this is a hard prohibition and not a preference: making feedback payload a monotone function of self-reported confidence creates a direct gradient toward miscalibrated confidence reports. It is the only proposed requirement in the entire set that could actively corrupt the training signal, and it would install preference-shaped incentive in a system whose founding invariant is that no preference reward exists. The underlying finding it came from (high-confidence errors are corrected most readily in humans) has never been tested as a feedback-allocation policy in any machine-learning setting, and its actual design implication, that feedback must include the reasoning and not just the answer, is already satisfied by L-10.*

### Human-facing academy surface

**L-15. Optional, skippable, re-enterable.** The academy is a sample project. It is always skippable, always re-enterable, and gates nothing. The scaffold-fade design is asserted in CI against the fixture content, never against any person's traversal. No completion tracking, no unlock gating on topic-sequence position, no cohort metric of any kind. *Reason: an unskippable tutorial is the stabilize-before-the-real-work anti-pattern in interface form, and a first-session pass-rate gate cannot be measured without instrumenting shipped builds, which zero-egress forbids.*

**L-16. Prominence.** On the **training report page**, delayed re-derivation is the most prominent metric; current-session accept rate, if shown, is visually subordinate and carries a persistent one-line note that session performance is a poor index of durable learning. This does **not** apply to the companion workspace, whose job is verifying the operator's own artifacts; making a model-training eval the most prominent element there is scope drift.

**L-17. Timing is operational fact, never score.** Elapsed and estimated-remaining for a run in flight, recorded duration in `receipt_envelope`, absolute timestamps on records: all permitted and in some cases required (the sludge audit measures elapsed times; factual duration forewarning is explicitly allowed). Prohibited: timing as score, target, or cross-session comparison, and any quantity derived from the person's absence or speed.

### Far transfer: what must not be claimed

**These claims are prohibited on every surface, and the null is preregistered:**
- That training on verified derivations makes a model generally more epistemically careful, more honest, more calibrated outside the trained distribution, or better at reasoning in general.
- Any single aggregate uplift figure. Near transfer (in-distribution, held-out items from the trained task families) and far transfer (out-of-distribution task families) are separately preregistered and separately reported.
- Any transfer claim broader than what was preregistered and measured.
Far transfer is the **preregistered null hypothesis** and is published when null. *Grounding: three independent lines converge, and this is one of the few genuine convergences in the whole document. Owen et al. 2010: 11,430 completers improved on every trained task and transferred to nothing, "even when those tasks were cognitively closely related." Simons et al. 2016 (PSPI consensus review): support for improvement on trained tasks, weaker for closely related tasks, little for distant transfer. Melby-Lervåg, Redick & Hulme 2016: 87 publications, 145 comparisons, reliable near transfer to working-memory measures, no convincing evidence of reliable far transfer against treated controls. The regulatory precedent for exceeding this bound is the FTC's $2M settlement with Lumos Labs, January 2016. The ML analogue (in-distribution versus out-of-distribution generalization) is independently real, so the requirement stands with or without the human literature.*

## 5. THE HONEST BOUNDS

### Ships verbatim as a docs page

**What CC-1 measures, and what it does not**

CC-1 verifies. It compares an artifact against a deterministic oracle at a frozen criterion and emits a receipt you can re-derive offline on a clean machine. Two things are measured and published: preregistered uplift, published even when null, and stranger offline reproducibility. A third, independent replication under a fresh seed and a fresh eval sample, is published as a separate number and is never pooled with the first.

Everything below is a bound we hold ourselves to. If you find us outside one of them, that is a defect, and the receipt for it goes in the ledger like any other.

**On how CC-1 treats you.** The design follows published trauma-informed and non-extractive design principles. We claim adherence to those principles. We do not claim measured benefit to you, because no trial has shown that any specific interface pattern reduces harm, and the organizational frameworks these principles come from are expert consensus rather than outcome-validated interventions. Where we say "the record cannot be tidied" or "nothing here counts against you except forged receipts," those are properties of the software you can test, not claims about how you will feel.

**On epigenetics.** CC-1 makes no epigenetic claim and does not use the word. There is no inheritance, lineage, generation, or ancestry vocabulary in the product, the schema, or the docs. Verdicts propagate across derivation steps and we count the steps; that is provenance, not heredity. For the record, since the surrounding culture makes the opposite assumption: transgenerational epigenetic inheritance is not established in humans, and the leading researcher in the trauma-transmission area writes that human studies "have not yet demonstrated that the effects of trauma are heritable through non-genomic (i.e., epigenetic) mechanisms" and that the epigenetic account "represents a hypothesis to be tested" (Yehuda & Lehrner, World Psychiatry 2018). The Dutch Hunger Winter work is direct in-utero exposure, that is, developmental programming, not inheritance. The Overkalix cohort contains no epigenetic measurement of any kind. We take from this field only its methods: count the hops, name the carrier, declare the erasure boundary, publish the composition of what you measured.

**On nervous-system and polyvagal vocabulary.** CC-1 uses none of it. No ventral or dorsal vagal states, no "regulate your nervous system," no window of tolerance as a label or a metric. An international group of 39 researchers evaluated polyvagal theory's core premises and judged them untenable against existing neurophysiology and evolutionary evidence (Grossman et al., Clinical Neuropsychiatry 2026); Porges published a rebuttal in the same issue. The dispute is unresolved, so no mechanism claim is available to anyone, including us. The window of tolerance has no validated instrument and no threshold; nothing in CC-1 senses or widens anything about you.

**On growth through difficulty.** CC-1 does not narrate growth, resilience, or transformation, and no uplift claim anywhere derives from a retrospective self-report of improvement. Retrospective perceived-growth instruments show poor construct and predictive validity, correlate weakly or not at all with measured pre-to-post change, and in several samples track greater distress rather than less (Jayawickreme & Blackie 2014; Gower et al. 2022; Gangel et al. 2024). Improvement claims here come from a preregistered pre-post measure or they do not exist.

**On brain training and transfer.** CC-1 makes no brain claim. Nothing here rewires anything, builds pathways, or trains a model like a brain. On transfer, we hold the field's own bound: training reliably improves the trained task, near transfer is weak, and far transfer has no convincing support. In one trial 11,430 completers improved on every trained task and transferred to nothing, including tasks that were cognitively closely related (Owen et al., Nature 2010); a consensus review (Simons et al., PSPI 2016) and a 145-comparison meta-analysis (Melby-Lervåg, Redick & Hulme 2016) reach the same conclusion independently. In 2016 the FTC settled with a brain-training company for $2M over claims that ran ahead of exactly this evidence. So: CC-1 reports near and far transfer as separate preregistered numbers, far transfer is the null hypothesis, and the null is published.

**On content and trigger warnings.** CC-1 has none, and this is deliberate rather than an omission. Meta-analysis finds warnings have no reliable effect on affective response to material and no effect on educational outcomes, while reliably increasing anticipatory anxiety (Bridgland, Jones & Bellet, Clinical Psychological Science 2024). Factual forewarning that lets you make a choice, estimated duration, number of failing checks, size of a diff, is different and is present. The test we apply: an element shown before a result is permitted only if its text changes when the underlying data changes.

**On accountability and repair.** The repair record's structure is imported from restorative practice: attribute the failed claim, compute what depended on it, publish the corrected derivation, and require a regression check that fails on the old state. We claim the structure. We claim none of the outcomes. The most recent meta-analysis of restorative justice (Fulham, Blais, Rugge & Schultheis, Criminology & Criminal Justice 2025; 27 studies, 34 samples) found roughly a 17 percent reduction in the odds of general recidivism, no significant effect on violent recidivism, and I-squared of 88.67, meaning extreme heterogeneity. Study quality inversely predicted effect size, and programs with minimal-to-some adherence outperformed high-fidelity programs. Import the structure. Do not claim the outcome.

**On psychological safety and blameless review.** The psychological-safety literature is large and overwhelmingly cross-sectional self-report; it cannot establish that safety causes learning rather than co-varying with it. There is essentially no controlled evidence that blameless postmortems reduce incident recurrence in software. Institutional honesty about failure has one robust finding: transparency did not make anything worse anywhere it was studied. "Apology reduces lawsuits" is weaker than commonly believed; the flagship result is a single-site before-after design and its multi-site replication was partial.

**On behavioral design.** No design decision in CC-1 is justified by the nudge literature, because that literature's headline effect does not survive publication-bias correction and shrinks roughly six-fold from academic samples to government-scale trials. Our bans on streaks, points, badges, levels, leaderboards, and inactivity notifications rest on a design commitment, that this tool will not be built to hold your attention, not on a claimed measured harm.

**On sleep.** CC-1 has no sleep feature, no sleep scoring, no circadian gating, and makes no sleep claim. The field-level effect of sleep on declarative memory has been downgraded by the senior author of its own canonical review as "probably smaller and less robust than previously assumed" (Cordi & Rasch 2021), and the dominant popular account contains documented factual errors.

**On our own numbers.** Any threshold, band, floor, interval or ratio you find in a CC-1 configuration is a local calibration unless a primary source is cited next to it. Spacing ratios in the memory literature come from verbal recall studies and are not validated for derivational tasks. The diversity floor we publish is a preregistered measurement, not a threshold any literature establishes; its single source is a 2025 preprint with a fitted empirical relation and competing mitigation proposals. Numbers we have not read in the primary source do not appear here at all.

**On what a receipt does not prove.** Every receipt carries this itself, in machine-readable form: which checks were not run, which inputs were not inspected, which properties were not asserted, and, when a verdict was propagated rather than re-derived, how many derivation steps away its evidence actually sits.

## 6. REJECTED

Killed by the lenses. Reason given so nobody re-proposes them.

**Human-facing mechanics**
1. **Retention/probe scheduler on the human side.** A due-state is a streak with a different name: it accumulates during absence and cannot exist without the tool modeling the person's retention. Replaced by pull-on-demand (L-8).
2. **Pre-verdict confidence solicited from the human.** A compulsory interstitial in front of every attempt plus a stored psychological record the design says must not exist. Replaced by L-14.
3. **Feedback depth scaled by the confidence-error gap.** Creates a direct gradient toward miscalibrated confidence and installs preference-shaped incentive in a preference-free system. The only proposed requirement that could corrupt the training signal.
4. **"No setting hides failures from the user's own record."** The tool overriding the practitioner's own view configuration on a clinical rationale (avoidance-as-maintainer) applied to someone who is not a patient. Immutability is a correctness property; view composition is the operator's business. Replaced by PC-12(b).
5. **Unskippable onboarding, plus a 90 percent first-session pass gate, plus "main-suite pass rate must not exceed the entry task."** The traversal mandate is the unskippable-tutorial anti-pattern; the 90 percent number is invented; the third probe is a coupled criterion that fails for reasons unrelated to onboarding. Replaced by L-15.
6. **Absolute ban on timers and elapsed-time display.** Bans operational timing the practitioner needs and other requirements demand. Replaced by L-17.
7. **"Pixel-identical screens at 1 day versus 400 days."** Fails permanently against any legitimate receipt-timestamp rendering. Replaced by "no rendered value is a function of `(now − last_activity)`."
8. **"Every table keyed by the user contains only settings and identity."** Vacuous in an accountless local-first app while the real risk (derived statistics under a run, workspace, or device key) passes it. Replaced by the quantity-level rule in PC-1.
9. **Verdict sort-priority invariance to blast radius.** Prevents triaging a 200-dependent failure ahead of a zero-dependent one, at no evidential gain; outcome bias is about how an action is judged, not about work ordering. Scoped to typography, color token and iconography.
10. **"No apply-all" as an absolute.** With blast radii reaching 200 mechanical re-derivations, forcing 200 individual commits is sludge. Replaced by PC-7's batch-as-one-reviewed-diff.
11. **Cohort and user-study falsifiers as release gates** (show 20 first-time users; first-session pass rate; ask five users; ">20% classify UNDECIDED as failure"). Not measurable without telemetry the product forbids, unsustainable per-release for one maintainer, and statistically fake: at n=20 a 20 percent threshold has a 95 percent interval of roughly 6 to 44 percent. Reclassified as one-time documented design reviews with n stated, reviewers named, raw responses published as an artifact, and no percentage gate. No evaluation may be instrumented in a shipped build.

**Fence violations**
12. **"The environment is punishing / the environment is forgiving," including as a biconditional definition or a requirement title.** Asserts an act on a subject. "Non-punitive failure accounting" is a property of an accounting scheme and remains permitted; the two are not interchangeable.
13. **Stressor-controllability (learned helplessness) as grounding for environment recoverability.** That literature is about detectors inside organisms, not about environments. The requirement survives its deletion perfectly, which proves the citation was decorative.
14. **Titration and pendulation as grounding for the curriculum sampler.** Somatic trauma-therapy technique for dosing a person's contact with distressing material, implying the model is dosed against a tolerance it can exceed. The same domain bans window-of-tolerance as unoperationalizable; this is the same family.
15. **"Who is hurt, what do they need, whose obligation is it," translated to dependent artifacts.** Installs artifacts as harmed parties with needs, which licenses the whole consequence vocabulary one category further out. Replaced by dependency invalidation (A-2).
16. **Restorative-accountability element names in the schema (attribution/impact/amends/non-repetition).** Moral-agent terms from a framework about people who have committed violence. Renamed to provenance fields (A-1). All four fields and both falsifiers kept.
17. **Global-self-evaluation as grounding for per-check credit assignment (training side).** Implies the model has a self the reward signal evaluates globally. Kept only for the human-facing string rule; the mechanism half is grounded in diagnosability and credit assignment.
18. **Abstinence-violation-effect as grounding for criterion freezing.** Implies a subject holding itself to a standard it can violate, using a construct that did not survive direct test even in humans. Replaced by measurement interpretability (M-2).
19. **Betrayal-by-legitimate-authority as grounding for reward terms.** Makes the model the betrayed party. Kept for the human-facing custodial-record argument only; the reward-side argument is signal validity (M-7).
20. **Coercion/escape-avoidance as grounding for history-independent environment state.** Implies the model escapes or is coerced, using evidence the same domain had already downgraded (Fontes & Shahan 2021 found the fallout claims weakly supported). Kept for the human half; the mechanism half is determinism (M-3).
21. **Proximal-process / PPCT as the definition of how the environment builds a capability, with a monotone "declared complexity metric."** The closest thing in the set to "learns like a child," and the complexity metric is unspecifiable: either trivially satisfied by declaring complexity equal to chain index, or it wrongly fails legitimate chains that plateau. The provenance content is already covered by M-10.
22. **Inheritance vocabulary in verdict tokens, receipt templates and user-visible sentences** (`PASS-INHERITED`, "inherited across N derivation steps"). Violates its own domain's anti-requirement and reinstalls the refused frame as a product surface. Renamed `PASS-PROPAGATED` (M-9). Nothing mechanical lost.
23. **Mandating the word "compensation" for repair records.** Lifted from a rat study about compensating for the neural effects of early adversity; presupposes a deficit in a subject. There is no deficit and no subject in a ledger, only a superseded record and an appended correction. The blocklist is kept and scoped (A-5).
24. **Blocklists reaching into commit messages, code comments, and private notes.** The tool managing the practitioner, in the one place a rule reached past the product into the operator's private working record. Scoped to shipped strings, receipt schema fields, and published docs (0.5).
25. **Any remorse, reflection, apology, or "lessons learned" field as a gate on completing a repair.** Mechanizing contrition converts accountability into performance, and a required field gets filled with whatever unblocks the gate, corrupting the record.
26. **Any nervous-system, brain, healing, or developmental language on any surface.** Covered by `fence-lint`.

**Unbuildable or unfalsifiable**
27. **FAIL-state reachability fraction over the environment state space.** Intractable, not merely expensive, for anything past a toy environment. A requirement satisfiable only by a number nobody can compute is worse than no requirement because it looks measured. Replaced by incident-recovery rate (M-5).
28. **`INHERITED-UNVERIFIED` as a stored fifth verdict state, with eager transitive propagation and "never stale at read time."** A mutation of an existing record (contradicting append-only), unbounded write amplification on a local store, a strong-consistency claim nobody needs with one process and one user, and a fifth token in a four-verdict vocabulary. Replaced by A-2.
29. **"Byte-identical run" falsifiers.** Unsatisfiable while other requirements mandate timestamps inside the record, and directly contradictory with the requirement that a resumed run append an interruption incident. Replaced by `receipt_core` equality (0.1).
30. **Static analysis proving absence of information flow through arbitrary indirection.** Undecidable in general, hopeless in Python with dynamic imports and file IO. A falsifier that cannot terminate provides no assurance. Replaced by sandboxed replay (0.2).
31. **CI that "walks every route and asserts against the five dark-pattern strategies and the fifteen types."** Detecting "sneaking" or "interface interference" in general is human judgment. As written it would be a denylist wearing a taxonomy's name, overstating the guarantee. Split into a concrete-primitive CI denylist plus a release-time human checklist published as a signed artifact.
32. **A linter detecting semantic double-use of glossary terms across all prose.** Undecidable; would be implemented as a keyword blocklist, produce constant false positives, and be disabled. An abandoned enforced-invariant is worse than none because the published claim outlives the check. Scoped to enumerated receipt-schema fields plus a denylist of known-ambiguous terms.
33. **"Visual weight measured as area × contrast."** An invented metric with no threshold and no validation, ignoring position, color, motion and whitespace, fully gameable by whoever implements it. Fake precision is worse for evidence honesty than an admitted judgment call. Replaced by a declared prominence enum plus a lint asserting FAIL views declare exactly one primary control and that it is not retry, skip or delete.
34. **"Every error string must contain a named check, an observed value and an expected value."** Breaks on the large class of environment and IO faults, and gets satisfied by fabricating empty fields. Scoped to verdict surfaces (PC-4).
35. **"Negative scope emitted by the oracle itself rather than authored as prose."** Self-contradictory: all negative scope is authored, the only question is when. Restated as a structured enumeration derived from the oracle's coverage manifest (A-6).
36. **An excess-significance flag that fires on any all-positive family.** No statistic and no threshold; fires constantly on families of three and teaches the maintainer to ignore it. Restated as a computed p-value against a declared alpha with an "insufficient tests" report below a stated k (L-5).
37. **Absolute guarantee that no record content appears in crash dumps.** Cannot be guaranteed free of heap contents on Windows without disabling dump generation. Stated as an absolute it would be quietly false. Replaced by "ships no crash reporter, disables OS dump generation, states the residual honestly" (PC-9).
38. **A requirement governing how to cite sleep research on surfaces discussing overnight gaps.** Dead code that invites someone to build the feature it regulates. Replaced by a flat prohibition on any sleep feature or claim.

**Evidence-honesty failures**
39. **Four independent groundings for one diversity floor.** Four expert reports converging reads as corroboration; exactly one grounding was about the phenomenon being measured, and it is a preprint. This is manufactured replication, the same failure mode that let a mortality-record association be read as molecular corroboration for two decades. Collapsed to one grounding (M-6). The same false-convergence pattern applies to criterion freezing and is resolved the same way (M-2).
40. **The 10 to 20 percent spacing ratio as a machine-side scheduler default.** A human memory parameter converted into a machine hyperparameter by vocabulary overlap on the word "retention." Replaced by L-9.
41. **"At least three task families" in probe composition.** The number is invented; the underlying study is 126 seventh-graders doing mathematics. Replaced by mixed-composition-recorded-in-receipt (L-10).
42. **Publishing specific undermining-effect d values next to the streak ban.** Implies a measured harm CC-1 has not measured and the literature has not established for this context; the effect is specific to tangible, expected, contingent rewards in a free-choice laboratory paradigm and was narrowed by a later 183-study meta-analysis. The ban stays, grounded on the design commitment.
