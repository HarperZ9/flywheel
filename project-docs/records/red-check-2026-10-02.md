# Red check: record of the first build and its measurement

Date: 2026-10-02. Status: report-only. Code: `harness/red_check.py`,
`harness/red_classify.py`, `harness/red_select.py`, `scripts/red_check.py`, and the
`red_check` job in `.github/workflows/ci.yml`.

## What it does

A test written against fixed code only shows that it encodes the expected behaviour
if it fails on the code before the fix, and fails for that reason. The red check
copies the parent commit into a scratch folder with `git archive`, lays the head
commit's new and changed test files over it, runs only the new and changed test
functions twice, and sorts each one:

| Class | Meaning | Credited |
|---|---|---|
| red-assert | failed on an assertion the test made, `pytest.raises` that did not raise, or `pytest.fail` | yes |
| red-missing-symbol | failed because a name the change adds does not exist yet, including an unexpected new keyword argument | no |
| red-error | any other exception, a fixture or collection error, or an AssertionError raised inside the code under test | no |
| skipped | the test skipped itself | no |
| green | passed on the parent commit | no |
| indeterminate | the two base runs disagree, the test does not pass at head, a run timed out, or an installed copy of the package shadows the scratch tree | no |

Three controls guard against a red that means nothing: the test must pass at head,
the base runs twice, and every top-level package of the scratch tree must import
from the scratch tree (`provenance`).

## Measurement

Corpus: 158 labeled cases from 60 commits across seven of our repositories (index,
forum, canon, flywheel, gather, mneme, crucible). Labels were written by reading the
base code and the test, never by running it on the base commit, and hashed before
the first run (labels sha256 `eefb3e28...e3d923450`). A case counts as flagged when
the check does not credit it (any class other than red-assert).

| Metric | Result | 95% Wilson interval |
|---|---|---|
| Precision on natural cases | 59 of 60 | 0.911 to 0.997 |
| Recall on natural no-credit cases | 59 of 59 | 0.939 to 1.000 |
| Recall on planted weakened or missing-symbol tests | 31 of 31 | 0.890 to 1.000 |
| False-positive rate on planted legitimate refactors | 0 of 8 | 0.000 to 0.324 |

It beats flag-everything (precision 0.570), flag-nothing, and random flagging at its
own rate (97.5th percentile precision 0.634, Youden J 0.395; the check's J is 1.0).
Class agreement with the labels: 154 of 158. Three disagreements are a definition
difference (an unexpected keyword argument naming a new parameter: labeled red-error,
classed red-missing-symbol); the fourth is one test the labeler expected to fail on
the base that passed there.

## Limits

- The agreement is high partly because the check executes what the labeler predicted
  by reading. It measures the cause classification and the controls more than
  judgement.
- Only 8 planted legitimate cases: the false-positive interval reaches 0.32.
- A red-assert shows the test failed on the old code on an assertion, not that it
  fails for the reason the author claims.
- It runs repository code. CI runs it on pull requests only and never fails a run.
